## 3. `.dockerignore` — what each line does

| Pattern | Reason |
|---|---|

| `.github` | CI workflow definitions. Not needed in the runtime image. |

## 4. `.env.example` — environment variable contract

This file is the committed template that documents every variable the codebase reads. `.env` (the real file) is gitignored; you create it via `cp .env.example .env` locally and fill in real keys. On Cloud Run, values come from Secret Manager.

| Variable | Purpose | Notes |
|---|---|---|
| `LLM_PROVIDER=auto` | Switch between LLM providers | `auto` tries Gemini first, falls back to NVIDIA on 429/auth errors. UI can override per request. |
| `GEMINI_MODEL=gemini-2.5-flash` | Gemini model id | Pinned so a rename is a one-line env fix, not a code change. |
| `NVIDIA_MODELS` | Comma-separated whitelist of switchable NVIDIA models | `deepseek-ai/deepseek-v4.1-flash,z-ai/glm-5.3-flash,nvidia/nemotron-3.5-lightning-30b-a3b` — the Streamlit dropdown picks from this list. |
| `NVIDIA_MODEL=deepseek-ai/deepseek-v4.1-flash` | Default NVIDIA model when UI selection absent | Switchable via env or per-request override. |
| `GOOGLE_API_KEY` | Gemini API key | Empty in example; real value from Secret Manager / local `.env`. |
| `NVIDIA_API_KEY` | build.nvidia.com API key | Same handling. |
| `TOP_K=3` | How many chunks go into the prompt | 3 is the sweet spot for Gemni Flash's context and free tier. |
| `TEMPERATURE=0.2` | LLM sampling temperature | Low = deterministic, less hallucination. |
| `RELEVANCE_THRESHOLD=0.35` | FAISS similarity score cutoff | Below it = empty retrieval = "Not in notes" without LLM call. Saves tokens and blocks hallucination. |
| `MAX_TOKENS=512` | Max response tokens | All three "flash/lightning" NVIDIA models and Gemini Flash operate comfortably within 512 (no long-reasoning traces). |

**Dropped `GCP_REGION`:** Cloud Run auto-injects `REGION` env var for free; storage/BigQuery SDKs resolve region from bucket URI. Region is a deploy-time flag (`gcloud run deploy --region=asia-south1`), not an app config.

## 5. `Dockerfile` — multi-stage `uv` build

Two stages:
- **Builder stage** (`FROM python:3.11-slim AS builder`): copies the `uv` binary from `ghcr.io/astral-sh/uv:latest`, then `COPY pyproject.toml uv.lock README.md ./` followed by `uv sync --frozen --no-dev --no-install-project`. `--frozen` guarantees exact `uv.lock` reproducibility; cache mount on `/root/.cache/uv` speeds repeated builds in CI.
- **Runtime stage** (`FROM python:3.11-slim`): copies only `.venv` and the source directory from the builder. Keeps the final image under ~800MB (vs. 2GB+ if build tools were copied).

`ENV PATH="/app/.venv/bin:$PATH" PYTHONUNBUFFERED=1 PORT=8080` — `PATH` makes `uvicorn` discoverable without `uv run` prefixes inside the container; `PYTHONUNBUFFERED=1` streams Cloud Run logs instantly; `PORT=8080` matches Cloud Run's expectation. `EXPOSE 8080` documents the listening port. Final `CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8080"]` is the container entrypoint — without it the container exits immediately and Cloud Run returns 503.

## 8. `api/main.py` — FastAPI entry point

This is the file Cloud Run boots. The Dockerfile's `CMD` references `api.main:app`, so the module path and variable name are contractual — `api/main.py` must expose a module-level variable named `app` that is a `FastAPI()` instance.

### Module structure

```
api/main.py
├── imports        — os, time, dotenv, FastAPI, Pydantic, generate/llm_client, retrieve/retrieval
├── load_dotenv()  — reads .env into os.environ (local dev only; no-op on Cloud Run)
├── app = FastAPI(title="RAG Course-Note Assistant — AI Textbook")
├── class Params   — in-memory singleton of runtime knobs (see below)
├── params = Params()  — loaded from env at startup
├── Schemas        — QueryRequest, Source, QueryResponse (Pydantic)
├── GET  /health   — liveness + provider status
├── GET  /params   — read current params
├── POST /params   — live-write params without redeploy
└── POST /query    — 3-stage RAG flow (the heart)
```

### `Params` singleton — live tuning without redeploy

Attributes: `top_k`, `temperature`, `relevance_threshold`, `max_tokens`, `llm_provider`, `nvidia_model` — each read from its env var at import time. The singleton lives in process memory so `POST /params` can mutate it live (useful for cost/latency experiments during the viva without a deploy cycle). Attributes not matching an env var are ignored silently (guarded by `hasattr`).

### Pydantic schemas

- `QueryRequest` — `question: str`, plus optional `provider` (`gemini` | `nvidia` | `auto`) and `model` (specific NVIDIA model id). These override `params` per request — this is the mechanism the Streamlit dropdown uses to switch models without redeploy.
- `Source` — `chunk_id`, `page`, `section`, `score`. The citation payload returned to the UI.
- `QueryResponse` — `answer`, `sources`, `llm_provider`, `llm_model`, `latency_ms`, `tokens_used`. The last two fields are the observability surface: Phase 2 logs every response to BigQuery's `query_logs` table for the Looker Studio dashboard.

### `/health` — Cloud Run liveness

Returns `{status, version, provider}` JSON, always 200, no external dependencies. This is the smoke-test endpoint CI hits after every deploy to verify the new revision is serving. It must never 500 even when the FAISS index is absent.

### `/params` (GET/POST)

`GET` returns the current singleton state as JSON; `POST` accepts a `dict` body and setattr's any matching attribute — enabling live tuning of retrieval and generation knobs without redeploying.

### `/query` — 3-stage flow

1. **Retrieve** — `retrieve(question, top_k, threshold)` runs FAISS + BM25 hybrid search and returns chunks scored above the relevance threshold.
2. **Empty retrieval → "Not in notes" without LLM call** — if `chunks` is empty, the endpoint returns a fixed "Not in notes. I could not find relevant passages in the indexed textbook corpus." with `sources=[]`, `llm_model="-"`, `tokens_used=0`. This is the core anti-hallucination + cost-saving trick: no LLM invocation means no tokens billed and no chance for a fabricated answer. (Currently the FAISS index is empty, so this is the expected response path until Phase 2 ingestion.)
3. **Generate** — chunks are formatted into a prompt (via `generate/prompt.py`, not yet written) and passed to `generate()` (dual-LLM facade). The `provider` and `model` from the request override the `params` singleton. A `Refusal` result (imported from `generate/llm_client`) is surfaced as "Not in notes. The indexed passages did not contain enough information to answer." — a second refusal channel for when retrieval succeeded but the LLM judges the passages insufficient.

### Imports set up for later modules

`api/main.py` imports `generate` and `Refusal` from `generate/llm_client`, and `retrieve` from `retrieve/retrieval`. These modules do not yet exist — the app will fail to import until both are created in the next blocks. That is intentional: Block 2 is split into three files delivered in sequence (`api/main.py` done, `generate/llm_client.py` next, `retrieve/retrieval.py` after) so each can be reviewed independently before running.

## 9. `generate/prompt.py` — system prompt + citation contract

**`SYSTEM_PROMPT` (5 invariants):** (1) answer only from passages, never outside knowledge; (2) cite every factual sentence as `[p.<page>, <chunk_id>]` with exact chunk id; (3) if passages insufficient -> `NOT_IN_NOTES` (+ one short missing-info sentence, no fabricated answer); (4) concise student text, no markdown tables unless passage has a table; (5) never give medical/legal/financial professional advice -> `NOT_IN_NOTES` + disclaimer.

**`build_messages(question, chunks)` -> `(system, user)`:** formats each chunk as a fixed header `[{chunk_id} | p.{page} | {section}]\n{text}` so the model references chunks deterministically; joins passages in source order with `---`; appends an explicit citation/refusal reminder. Both adapters in `llm_client.py` receive this pair verbatim — the contract is identical across providers.

**`is_refusal(answer)`:** True when raw output starts with `NOT_IN_NOTES` (case-insensitive). Contract between generation and validation: `llm_client.py` maps it to a structured `Refusal`, surfaced by `api/main.py` as "Not in notes" rather than a fabricated answer.

**Module 3 (ethical AI) why:** the refusal channel + citation requirement are the two implemented mitigations for hallucination, enforced identically across both LLM providers.

## 10. `generate/llm_client.py` — dual-LLM facade

**Adapters (one interface, two backends):** `GeminiAdapter` (google-genai SDK, `generate_content(config={system_instruction, temperature, max_output_tokens})`, tokens from `usage_metadata.candidates_token_count`) and `NvidiaAdapter` (OpenAI client to `https://integrate.api.nvidia.com/v1`, `chat.completions.create`, tokens from `usage.total_tokens`). Both implement `complete(system, user, temperature, max_tokens) -> (answer, tokens)`. Lazy imports in `__init__` keep Cloud Run cold starts fast when only one provider is used; no GPU binding, no self-hosted NIMs.

**`Result` / `Refusal` dataclasses:** success carries `answer+provider+model+tokens_used`; refusal carries `reason+provider+model`. Produced by (a) `is_refusal()` True or (b) citation validation failing. `api/main.py` pattern-matches the two.

**`_validate_citations(answer, chunk_ids)` — Module 3 enforcement:** regex `\[\s*p\.\s*([^\],]+)\s*,\s*([^\]]+)\s*\]` extracts every `[p.<page>, <chunk_id>]`; returns False when no citations or any cited id is not in the retrieved set. Failed validation becomes a Refusal — the LLM cannot return an answer with a fabricated source id.

**`generate()` facade:** `provider="gemini"/"nvidia"` -> single adapter; `"auto"` -> Gemini first, NVIDIA on any exception (429/auth/upstream). Optional `model` overrides env default so the Streamlit dropdown can switch DeepSeek/GLM/Nemotron per request without redeploy. Identical `(system, user)` from `prompt.py` to all providers.

## 11. `retrieve/retrieval.py` — hybrid retrieval (FAISS + BM25 over RRF)

**`load_index()` at import:** reads `index/faiss.idx` + `index/chunks.json` (overridable via `FAISS_INDEX_PATH`/`CHUNKS_META_PATH`; GCS download wired in Phase 2). Rebuilds BM25 over chunk texts. If files missing (MVP state), sets `_INDEX=None`, `_CHUNKS=[]`, returns 0 — never raises, so Cloud Run cold starts don't crash.

**Embedder:** lazy singleton `SentenceTransformer("BAAI/bge-small-en-v1.5")` — 33M params, 384-dim, CPU-friendly. Lazy loading keeps imports fast until first query.

**`retrieve()` 5-step pipeline:** (1) embed query + normalize to unit length; (2) FAISS `IndexFlatIP` top-20 dense search; (3) BM25 top-20 keyword search; (4) Reciprocal Rank Fusion (`1/(60+rank)`) merging rankings rank-only — sidesteps dense-vs-BM25 score scale mismatch; (5) relevance filter — chunks with dense similarity >= threshold (default 0.35) survive; BM25-only chunks pass if RRF ranks them high (recall). Returns up to `top_k=3` dicts with `chunk_id/page/section/score/text`.

**Empty-index guarantee:** if `_INDEX is None or not _CHUNKS`, `retrieve()` returns `[]` immediately. `api/main.py` converts that to "Not in notes" with `llm_model="-"`, `tokens_used=0` — no LLM call, no tokens billed, no possible hallucination. Expected path until Phase 2 builds a real index.

## 12. `ui/app.py` — Streamlit chat UI

**Backend coupling via HTTP:** `API_URL` env (default `http://localhost:8000`) + `httpx` calls `/health` (sidebar status) and `/query` (per-turn answer). UI never imports `api.main` directly — FastAPI and Streamlit are separate Cloud Run services.

**Provider dropdown end-to-end:** the Streamlit radio maps to `(provider, model)` tuples sent in the `POST /query` JSON. DeepSeek / GLM / Nemotron all route through `nvidia` + the specific model id from `NVIDIA_MODELS`; `Auto` sends `provider="auto"` (server fallback logic picks); "Gemini (default)" is the default selection. This is the per-request override wired through `QueryRequest.provider/model` in `api/main.py`.

**Chat history + sources:** `st.session_state.messages` persists across turns; each assistant entry carries its `sources` list, rendered in a collapsible "Sources" expander (`chunk_id`, page, section, score). The expandable citation view makes the citation contract visible in the demo.

**Failure modes are graceful:** API unreachable at boot → sidebar shows an error instead of a crash. Backend timeout (120s per query) → `st.error` + `st.stop()`, never a traceback.

## 16. Phase 2 ingestion — `ingest/parse_pdf.py`, `chunk.py`, `embed.py`

**`parse_pdf.py`** — PyMuPDF `page.get_text("text")` extraction (text layer, not OCR). Flags table-containing pages via `page.find_tables()`. Empty-text pages (scanned images with no text layer) are silently skipped — the caller logs a warning and you note them in `model_card.md` limitations for the viva.

**`chunk.py`** (original, pre-overhaul) — heading-aware recursive splitting: 500-token target, 80-token overlap, every chunk prefixed with `Chapter N | {section} |` so retrieval carries section context. Per-page chunking instead of global sliding window. **Flaws found in overhaul audit:** heading regex captured only the group (`Chapter` / `3.2`) not the full heading; only first heading per page used; new `current_section` never reset per chapter/page; chunk counter global (not per-page), so `AI Engineering:p27_c025` meant the 25th chunk overall.

**`embed.py`** — BGE-small `SentenceTransformer` embeds chunks (384-dim, L2-normalized for cosine), builds FAISS `IndexFlatIP`, writes `index/faiss.idx` + `index/chunks.json`. **Flaw:** no `passage:` prefix — docs embedded without the BGE training-format prefix, causing measurable dense-score degradation vs queries.

## 17. `api/main.py` tuning fixes (Refusal `tokens_used` crash + CORS)

**`getattr` guard for Refusal path.** When `generate()` returns a `Refusal`, `result.tokens_used` raises `AttributeError: 'Refusal' object has no attribute 'tokens_used'` — turning what should be a clean `200 "Not in notes"` into a 500. Fixed by `tokens_used=getattr(result, "tokens_used", 0)` at line 143.

**`load_dotenv()` in `generate/llm_client.py`.** Standalone Python diagnostics (`python -c "from generate.llm_client import generate"`) skipped the `load_dotenv()` call that `api/main.py` normally does, so `NVIDIA_API_KEY` was empty outside the API process. Fixed by calling `load_dotenv()` at module import in `llm_client.py` itself.

**CORS middleware.** The Streamlit browser (at `http://localhost:8501`) was blocked from calling `http://localhost:8000` with `Access to fetch at 'http://localhost:8000/health' has been blocked by CORS policy`. Added `CORSMiddleware` with `allow_origins=["*"]` (student demo); Phase 3 will whitelist `localhost:8501` + the Cloud Run UI URL.

## 18. RAG retrieval full overhaul — chunking + BGE prefix + tokenization

**`ingest/chunk.py` (overhaul):** three-level heading detection (chapter `CHAPTER 2`, numbered section `2.1`, ALL-CAPS title), full heading text captured via finditer (not just regex group), `current_section` updated on every new heading and reset per chapter, sentence-aware fallback (`_split_sentences` splits oversized paragraphs so no chunk overflows the 500-token target by more than one sentence), and per-page chunk IDs (counter reset per page). Result: 721 chunks (vs 529 before) with section paths that survive retrieval — heading prefixes like `Chapter 2 > Understanding Foundation Models |` now land on every chunk.

**`ingest/embed.py`:** docs are now encoded with the BGE `"passage: "` prefix (`texts = ["passage: " + c["text"] for c in chunks]`). Queries in `retrieve()` use the matching `"query: "` prefix. This is the correct BGE training format and alone typically improves hit@3 by 10–20%.

**`retrieve/retrieval.py`:** query encoding now uses `"query: " + query`; BM25 tokenization fixed from naive `split()` to `_bm25_tokens()` (lowercase alphanumeric, `len > 2` filter) so docs and queries are tokenised identically. The threshold filter stays strict (`if sim >= threshold:`) — the BM25-only bypass (`score 0.0` chunks reaching the LLM) stays removed.

**Index rebuilt:** `uv run python ingest/embed.py "./AI Engineering.pdf" --out ./index` — 529 pages → 721 chunks → `faiss.idx` 812 KB + `chunks.json` (heading-aware, passage-prefixed embeddings).

## 19. Eval: exact hit@3 + MRR (replacing the keyword proxy)

**Before:** `eval_hitrate.py` implemented only a keyword-overlap proxy (`hit >= 2` expected keywords present in concatenated retrieved text). MRR was not computed at all. **After:** exact hit@3 (`len(set(retrieved_ids) & set(gold_ids)) >= 1`), MRR (mean reciprocal rank of first gold chunk), and refusal accuracy (already correct) are computed and written to `eval/metrics.json`.

**Gold ID correction:** the overhaul changed the chunker from a global counter to per-page numbering, so old gold IDs (`AI Engineering:p27_c025`) do not exist in the new index. The mapping was taken from the actual `failed_cases.json` retrieval output and a keyword scan of `chunks.json` (e.g. tokens definition is now `AI Engineering:p27_c031`, not `p27_c025`). All 10 answerable questions now have `expected_chunks` pointing at real chunks in the 721-chunk index.

## 25. Live PDF upload feature (in progress)

**Design decisions:**
- **Inline ingestion during the request** — Cloud Run allocates CPU during request handling (background-after-response work gets throttled CPU). Ingestion of a small PDF runs seconds-to-minutes in-request; Cloud Run rag-api timeout must be raised to 900 s in the Console before testing uploads on the live URL.
- **Incremental append, not full rebuild** — new chunks are embedded and appended to the live FAISS index (`.add()`); existing chunk IDs stay valid; BM25 rebuilt over the full corpus. A new document ingests in seconds instead of re-embedding 721 chunks (~3.5 min).
- **Persist to bucket after upload** — `faiss.idx` + `chunks.json` written locally and uploaded to bucket `rag-index-514120` (same object names the cold-start download expects), so the enlarged index survives cold starts.
- **Duplicate source → 409** ("already indexed") — chunk IDs are namespaced per source (`{source}:p{page}_cNNN`), so re-uploading the same source would collide. Document delete/re-index is out of scope (FAISS removal needs `IndexIDMap`).
- **Constraints:** Cloud Run request body cap 32 MB → `/upload` enforces ≤30 MB; scanned/image-only PDFs → 400 with "OCR not supported" message (matches model_card limitations).

**Block 1 (done):**
- `ingest/parse_pdf.py` — `parse_pdf` now accepts `str | bytes`: bytes are parsed via `fitz.open(stream=..., filetype="pdf")` (live upload path — no temp files on Cloud Run's ephemeral disk)
- `ingest/pipeline.py` (new) — `ingest_pdf_bytes(pdf_bytes, source_name, model=None) -> {chunks, embeddings, pages}`: runs the same heading-aware chunking + BGE `passage:`-prefixed embedding as the original index build, so new vectors are directly comparable with existing ones. Raises `ValueError` on scanned/empty PDFs (clean 400 response). `model=` accepts the API's already-loaded SentenceTransformer to avoid loading a second copy per upload.

**Block 2 (done):** `retrieve/retrieval.py` gained three functions: `indexed_sources()` (duplicate-upload check), `add_documents(new_chunks, new_embeddings)` (FAISS `.add()` append + `_CHUNKS` extend + BM25 rebuild; handles the empty-index case by creating a fresh `IndexFlatIP`), and `persist_index()` (writes `faiss.idx` + `chunks.json` locally, uploads both to bucket `rag-index-514120` — same object names the cold-start download expects; returns False gracefully in local-only mode without GCP credentials).

**Block 3 (done):** real `POST /upload` in `api/main.py` — multipart `UploadFile`, guards ordered cheapest-first (30 MB limit → `%PDF-` magic-byte check → 409 duplicate via `indexed_sources()` → ingest), CPU work via `run_in_threadpool` (keeps the event loop responsive — health checks stay live during multi-minute ingestions), `python-multipart` dependency added. Plus `GET /documents` (lists indexed sources + chunk count) and a 413 response for oversized PDFs. Errors are typed: 400 scanned/non-PDF, 409 duplicate, 413 oversize — never a 500.

**Block 4 (done):** `ui/app.py` sidebar "📄 Upload PDF" — `st.file_uploader` + "Ingest this PDF" button → multipart POST (timeout 600) → success metrics (pages → chunks → new corpus total) + `st.toast` "searchable now"; 409 → info box; other errors → error box.

**Block 5 (done):** `tests/test_upload.py` — 5 tests, fully isolated via an autouse fixture (swaps module globals for a 1-chunk fake index, redirects `FAISS_INDEX_PATH`/`CHUNKS_META_PATH` to `tmp_path`, sets `GCS_INDEX_BUCKET=""` so persist goes local-only — tests never touch the real `index/` or the GCS bucket): ingest+index round-trip, duplicate → 409, non-PDF → 400, oversize → 413, `/documents` listing.
